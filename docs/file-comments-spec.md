# Upstream file comments: implementation reference

Source baseline: official 7-Zip 26.03. The focused FS/ZIP Comment command is
implemented. Current safety differences are listed below. The earlier scoped
results are historical evidence; the later ZIP writer fixes and release checks
are recorded in zip-metadata-port.md and release-consolidation.md.

- `UI/FileManager/PanelOperations.cpp::ChangeComment`, `PanelKey.cpp` and
  `ComboDialog.*`: edit the focused item only (not the selected set), excluding
  the parent item, through a single-line dialog initialized with its current
  value. Ctrl+Z invokes Comment. Refresh preserves selection afterward.
- `FSFolder.cpp::LoadComments/GetProperty/GetRelPath`: lazily read the current
  folder's `descript.ion` as UTF-8, with or without BOM. No ANSI/UTF-16 fallback;
  reads at least 256 MiB or failed conversion yield no comments. Flat children
  do not load separate child comment files. Display strips U+0004 and its tail.
- `TextPairs.cpp::CPairsStorage` and `FSFolder.cpp::SaveComments/SetProperty`:
  case-insensitive IDs, trimmed filename/value pairs, quoted space-containing
  filenames, empty-value removal, case-insensitive sort. Save as UTF-8/CRLF;
  non-ASCII content receives `EF BB BF 0D 0A`. Empty storage leaves an empty file.
  Flat children are not editable. Rename/delete do not update comment pairs.
- `Agent/ArchiveFolderOut.cpp::SetProperty`, `AgentOut.cpp::CommentItem` and
  `Agent.cpp::CanUpdate`: archive entry comments are writable for ZIP only,
  one actual entry at a time; virtual folders are rejected. This does not mean
  editing the whole archive's comment. Existing update/device/tail constraints
  still apply.
- `Archive/Zip/ZipItem.cpp::GetUnicodeString`, `ZipHandler.cpp::GetProperty`
  and `ZipHandlerOut.cpp`: decoding uses the UTF-8 flag, Unicode Comment extra
  and code page rules. Writing follows the entry's existing UTF-8/OEM choice,
  not merely whether the new comment has Unicode characters. Limit: 65,535 bytes.

Upstream FS saving ignores several write failures and has no external-change
check. A port should retain compatible data semantics while detecting errors,
conflicting writes, symlinks and ambiguous/unrepresentable names. Preserve
unrelated pairs and original filesystem metadata during a guarded replacement.
Case-sensitive volumes containing `A` and `a`, duplicate IDs, quotes, tabs and
newlines need explicit handling; inventing an escaping format would break
compatibility.

## Implemented path

`MainWindowComments.cpp` provides File → Comment / Ctrl+Z and the local context
menu. A focused, non-parent item is edited even when a different set is selected.
The title is `<name> : Comment`, with the upstream Comment label and existing
value. Selection and focus survive refresh. Unsupported archive formats and
virtual ZIP folders are disabled; Windows instead lets some of these fail when
saving. Native ZIP rows in Flat view are editable, including descendants;
filesystem Flat descendants retain their separate descript.ion limitation.
The Comment columns can be enabled through the header menu and sorted.

`FileComments.cpp` reads on workers and imports the original TextPairs bodies, including
ASCII space/tab/LF trim before CR removal, quoted space-containing names,
case-insensitive UTF-16-unit ordering, CRLF and the upstream non-ASCII BOM prefix.
The pinned `TextPairs.h` / `TextPairs.cpp` parser, binary FindID, AddPair,
DeletePair and SaveToString are generated by `scripts/import-file-comments.py`.
The original `Common/MyVector.h` pointer heap sorter is imported too. QString
adapters retain Windows UTF-16 units and original method semantics; cancellation
checks are added between input records. The pointer sorter has sentinel storage
for its original one-based indexing. There is no invented serialization format.
The former lower-bound lookup and stable sort were not equivalent for duplicate
IDs: three equal IDs are reordered by the original heap sort, and FindID returns
the middle match. Reading now follows that original behavior; ambiguous writes
remain explicitly refused. Ownership/permissions/concurrent-change protection
and private UTF-8 decoding remain in the macOS file adapter.

The scanner reads only the current folder's file, with full relative paths for
Flat entries. Invalid UTF-8/oversize files display no comments; editing reports
an error instead of overwriting unreadable content. Rename/delete do not rewrite
pairs, as upstream does not do so. Writes preserve unrelated pairs, ownership,
mode, ACL and extended attributes through a same-folder temporary replacement.
Existing comment-file timestamps are updated by the write, as upstream does.

ZIP saving now imports the original `CAgent::CommentItem` body and executes it
through bundled `7zz-progress`. It uses one focused `GetRealIndex`, `CommentIndex`
and original NoChange update pairs. Same-name siblings remain separate items;
the GUI captures row identity when opening the dialog and restores focus/selection
by identity after the update. `ZipCommentHelper.cpp` remains a structured-property
reader for listing fallback. Engine serialization/codecs/crypto are not reimplemented.
All existing 7-Zip LGPL/BSD/unRAR notices, unchanged upstream source and imported
port sources remain in the bundle. See [the source port](native-agent-comments.md).

ArchiveBackend Comment copies into private staging, resolves the native row,
updates, re-lists and checks entry count/order and semantic properties. Only the
chosen comment may change. It verifies the original stat/SHA-256 again and
preserves prefix, ownership, ACL/xattrs/mode before atomic replacement. Comments
use an owner-only UTF-8 file; passwords remain stdin. Packed data is unchanged,
so this metadata-only operation does not impose a whole-archive Test or an
unrelated old-data password. Pause/Cancel apply to worker copying/commit and
asynchronous child processes. Failed validation and cancellation retain the original.

## Limits and intentional protections

- Editing ambiguous names/duplicate IDs, quotes/tabs/newlines, invalid UTF-8,
  symlink or hard-linked descript.ion and read-only/permission failures is refused.
  Round-trip validation prevents silently damaging an unrelated unrepresentable
  pair. New comment-file creation uses exclusive rename; normal concurrent edits
  are checked before commit. This is not a global lock against a writer racing
  inside the final existing-file rename.
- The case-sensitive `A`/`a` volume condition is guarded by the same name comparison,
  but a case-sensitive mounted volume has not been exercised on this Mac. Actual
  whitespace-trim collisions and case-insensitive duplicate comment IDs are tested.
- ZIP comments are per-entry, not archive-global editing. Empty values delete
  them; the official writer enforces 65,535 encoded bytes. The normal GUI/native
  helper accepts up to 4 × 65,535 bytes of private UTF-8 transport, so the final
  field limit is checked by the handler. The legacy standalone helper retains
  its 65,535-byte UTF-8 limit; the GUI resolves real rows and uses the native helper.
- ZIP legacy OEM/code-page handling follows the official macOS source and is not
  identical to a Windows OEM locale. ASCII/Japanese UTF-8 fixtures are verified;
  exhaustive legacy code pages and Unicode extra variants remain unverified.
- The upstream target-header rewrite can add an NTFS timestamp extra to a DOS-only
  timestamp (same instant, added zero precision) and remove unknown target extras.
  Raw target-header byte identity is not claimed. Unrelated local records, target
  compressed data and decoded contents are independently compared in fixtures.
- Signed ZipCrypto data-descriptor updates are supported by the bounded original
  writer overlay in [zip-metadata-port.md](zip-metadata-port.md). It preserves the
  password-check flag/time and encrypted bytes. Unsigned descriptors retain the
  original handler's E_NOTIMPL for metadata updates; Test/extraction remains
  available. Metadata-only comments need no unrelated data password. A successful
  comment change does not imply that already corrupt unrelated payloads pass Test.
- Single-layer leading offsets now retain the original stub/prefix using the
  official ZIP handler, with prefix-byte verification before installation; see
  [archive-prefix-updates.md](archive-prefix-updates.md).
- Multi-volume, tail or unsupported layouts remain read-only for this
  mutation. Writable handler warnings are now supported, following the original
  Agent; see [update-safeguards.md](update-safeguards.md). Split/
  multi-volume browsing/extraction still uses 7zz; its comment display uses
  normalized console values rather than the single-stream helper.
- The original single-line editing workflow is connected. Physical Ctrl+Z/native
  menu interaction and rendered pixel comparison await an unlocked desktop.

## Verification

`comment_tests` / CTest `file_comments` covers actual filesystem saving, metadata,
permission/change/cancellation cases and focused GUI workflows, together with
ZIP64, Deflate/BZip2/LZMA, AES/ZipCrypto, maximum-length comments, virtual folders,
duplicate ZIP names and split ZIP read/extract regressions. Python's zipfile reads
independently verify decoded bytes, raw compressed payload, unrelated local records,
comments and archive-global comment preservation. Results and executed commands
are recorded in [test-results.md](test-results.md).
